# ADR-0024: clang-tidy's first real local run — expanded checks, fixed include hygiene, everything else triaged and deferred

Status: Accepted
Date: 2026-08-06

## Context

`clang-tidy` has been part of CI since ADR-0012, non-blocking, and had never actually run on this machine — no LLVM install, which ADR-0012 flagged explicitly rather than assumed away. A full audit pass installed it (`brew install llvm`) and ran it for real, for the first time, against every file in `src/`.

## Decision

Expanded `.clang-tidy`'s checks to include `misc-*` and `clang-diagnostic-*` — neither was enabled before, and both are exactly where "unused code or import" findings live (`misc-include-cleaner` for includes, `clang-diagnostic-unused-*` for dead variables/parameters).

First real run (after fixing an environment mismatch — Homebrew's clang-tidy needed `-isysroot` pointed at the Xcode SDK, since the compile database was generated by Apple Clang but analyzed by a different clang install): 216 warnings, 2 hard errors. Both errors turned out to be the same sysroot mismatch, not code defects — re-running with the right sysroot dropped errors to zero and raised the warning count to 422 (more files actually got analyzed instead of failing outright), 44 of them `misc-include-cleaner` findings.

Every `misc-include-cleaner` finding got fixed — 43 were "this type is used but its defining header isn't included directly" (relying on transitive inclusion through another header, which breaks silently if that header ever changes what it includes), one was a genuinely unused `#include <iostream>` in `CSVParser.h`. Added the missing direct includes (`<cstddef>`, `<cstdint>`, `<functional>`, `<exception>`, `<iterator>`, plus a few missing internal headers like `engine/Types.h` and `engine/Order.h`) across ten files, removed the one unused one. Zero `misc-include-cleaner` findings remain.

Zero genuine unused-code findings turned up anywhere — no dead variables, no unused parameters, no unreachable branches. The two `bugprone-exception-escape` findings (both benchmark binaries' `main()` not catching every possible exception) are expected, not defects: an uncaught exception terminating a CLI tool with a message is normal, acceptable behavior, not a bug to suppress with a blanket catch-all that would hide real failures instead.

## Alternatives considered

**Fixing all 378 remaining warnings in this pass** (`misc-const-correctness`, `cppcoreguidelines-pro-bounds-avoid-unchecked-container-access`, `readability-identifier-length`, and similar) was considered and rejected. These are real, legitimate style/robustness suggestions — not defects, not dead code, not unused anything — and several (like switching `operator[]` to `.at()`, which changes out-of-bounds behavior from undefined to throwing) need case-by-case review to confirm the change is actually correct for that specific call site, not a mechanical find-and-replace. Blitzing through 378 findings in one pass risks introducing a real bug in the name of fixing a style warning, which is worse than leaving the warning tracked and non-blocking — exactly the reasoning ADR-0012 already gave for keeping this check non-blocking in the first place.

## Consequences

The two questions this ADR actually needed to answer — "is there unused code or unused imports anywhere" and "does clang-tidy even run clean here" — both have real, verified answers now instead of an untested assumption: no unused code exists, include hygiene is fixed, and the only errors were environmental, not code defects. The remaining 378 warnings are real findings, triaged and consciously deferred, not unknowns — a future pass tightening `misc-const-correctness` and the bounds-checking suggestions has a concrete, already-categorized list to start from rather than a blank slate.
