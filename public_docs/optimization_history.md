But it's not a clean win: 3.0's bitmap scan always starts from the array edge with no cached "current best price," so its cost scales with how far the nearest occupied tick is from the edge. See ADR-0021 for the full mechanism and the identified (not yet built) fix: cache the best-price tick, only rescan when it empties. |

## Future Work
*   Cache the current best-bid/best-ask tick in 3.0 rather than always rescanning from the array edge (ADR-0021) — likely closes most of the Worst Case regression at no cost to the workloads that improved, and is the natural next increment before calling 3.0 "done" rather than "measured."
*   4.0 (reconsider the `OrderId → OrderLocation` cancellation index) is the next planned structural change.
*   2.0 and 3.0's absolute numbers above should both be re-measured on an idle machine before being treated as authoritative; the relative comparisons are sound regardless.
*   The per-category variation noted in 2.0's takeaway (why Instruction Delivery vs. Instruction Processing improves more in different workloads) is now partly explained by 3.0's data (occupancy density), but not completely — still worth revisiting once the best-price cache exists and isolates the remaining variable more cleanly.
